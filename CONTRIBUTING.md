# Регламент разработки

## Процесс работы над задачей

1. **Выбор задачи:**
   - Откройте доску [Projects](https://github.com/orgs/reflexum/projects) или список [Issues](https://github.com/reflexum/coffee-schedule/issues). Задачи с меткой `good first issue` подходят для быстрого старта.
   - Проверьте секцию «Зависит от»: если блокирующие задачи ещё не закрыты, выберите другую.
   - Назначьте задачу на себя (Assignee). Если в требованиях есть неоднозначности, обсудите их в комментариях к задаче до написания кода.
   - Незавершённую работу и текущий статус отмечайте на проектной доске.

2. **Ветвление:**
   - Создайте ветку от актуального `main`:
     ```bash
     git checkout main
     git pull
     git checkout -b issue-<номер>-<краткое-описание>
     ```
     *Пример:* `issue-2-employee-entities`

3. **Разработка и Pull Request:**
   - Делайте понятные, атомарные коммиты.
   - Если хотите заранее обсудить промежуточное архитектурное решение или показать незавершённую работу коллегам, откройте **Draft Pull Request**.
   - При оформлении PR заполните чек-лист по шаблону [.github/pull_request_template.md](.github/pull_request_template.md) и укажите номер закрываемой задачи: `Closes #<номер>`.

4. **Блокеры и задержки:**
   - Если возникли блокеры, изменились приоритеты или задача откладывается — оставьте короткий комментарий в Issue, чтобы команда была в курсе статуса.

## Правила ревью и слияния (Merge)

- Прямой push в `main` запрещён — все изменения попадают в основную ветку только через Pull Request.
- Перед слиянием обязательны:
  - Успешное прохождение CI (компиляция решения, запуск тестов и проверка стиля `dotnet format`).
  - Одобрение PR от ревьюера (Peer Review).
- Замечания и предложения на ревью обсуждаются непосредственно в комментариях к коду.
- После успешного слияния PR связанная задача закрывается автоматически, а рабочая ветка удаляется.
